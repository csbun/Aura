# 0.4.3：事件由 Aura 管理

标签方案依赖照片旁的 XMP，相册方案会让自动事件混入用户相册。改为 Aura 保存事件名称、照片 ID 关联及纠错记录；图库仍只由 Immich 管理。

## 迁移

- 自动归档 `aura.pre-0.4.3.sqlite`，升级到 Schema 8；不复制照片。
- 只读取 Aura 已记录 UUID 的标签，保留当前名称、完整成员、人工状态和事件 UUID，不按名称接管普通标签。
- 全部读取成功后，一次事务写入事件、转换规则，移除旧标签管理和任务表。缺失标签、权限不足或读取失败会暂停，不提交部分结果。
- 旧版仍有未完成标签操作时暂停，升级前在 0.4.2 完成或取消它们；若已升级，则先停 Aura 并恢复本次归档再处理。尚未迁成标签的旧本地事件可直接保留。
- 规则中的事件标签条件改为 `event_ids`；普通标签仍为 `tag_ids`，同时满足的语义不变。旧删除事件的抑制记录保留。

迁回后，Immich 标签与 Aura 事件互不修改。旧标签和 XMP 暂留作为历史结果，程序不批量删除文件；新事件操作不产生任何 XMP。已存在的规则相册继续工作，新事件默认不生成相册。

## 部署

NAS `/photos` 和样本 `/samples` 使用只读挂载，Aura 仍无照片挂载。移除任务管理员 key 和标签写入开关。已有旧读写卷保留但不再挂载。

恢复旧版须停止 Aura 与 worker、恢复对应归档并使用旧代码；不能仅降级镜像。恢复 Aura 不会撤销已发生的 Immich 相册操作。

## 验证

2026-10-22：50 项自动测试通过，覆盖事件不写标签/不自动建相册、迁移失败回滚与重试、规则转换、人工调整、删除抑制和相册保护。JS 语法及格式检查通过。

当前样本环境已部署 0.4.3：199 个事件、942 张照片的名称、UUID 与全部成员和迁移前快照一致；942 张原图及 942 个已有 XMP 校验值未变。Immich 旧标签未修改。

`/photos`、`/samples` 均只读，Aura 无照片挂载；迁移、事件、相册任务全部完成，无错误。重复整理新增/更新均为 0。真实事件预览、临时相册成员和重试通过，删除测试事件后规则暂停且相册照片保留，临时相册已清理。
