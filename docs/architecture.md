# 架构：Immich 是照片数据源

下述当前实现为 0.4.1；0.4.2 的标签整合目标见后文，尚未实施。

```text
NAS 原图 ──只读 SMB──> 官方 Immich ──公开 HTTP API──> Aura
                        │                            │
                   照片、人物、标签              事件、规则、Immich ID
                   缩略图、模型、搜索            定时维护规则相册成员
```

## 职责

- Immich：索引、元数据、缩略图、人物识别/命名/纠正、标签、语义索引、照片浏览。
- Aura：事件自动整理、合并/删除、自然语言到可编辑条件、组合规则、相册成员维护。
- Aura Web 与 worker 共用本地 SQLite；两者均无 NAS 挂载、Pillow 或第二套识别任务。
- 预览图片由 Aura 后端代理 Immich，API key 不交给浏览器。UI 通过公开浏览器地址跳转 Immich，无 iframe 或源码补丁。

## 数据与任务

常驻表仅有事件、事件到 Immich 照片 ID 的关系、相册规则（含远端相册 ID）、配置和任务状态。照片元数据仅在请求/事件计算期间存在内存；不持久化人物/标签目录或资产映射。

每日从 Immich 分页读取照片以生成事件；每 5 分钟按规则直接搜索并更新相册。时间事件默认通过，自动事件按成员重叠保留 ID 并补入新照片；人工命名、旧版手动确认及合并事件成员固定。事件计数是保存的成员数，预览会排除上游已删除、离线或不可访问照片。可手动合并跨日事件。0.5 计划综合时间、地点、人物和画面识别完整活动，支持跨日与缺少 GPS 的情况，并自动生成有依据的事件名称；具体场景见 [路线图](../ROADMAP.md)。这些识别与命名能力尚未实现。

组合查询交给 Immich `filter`，事件通过 ID 集合求交；元数据搜索使用 `nextCursor` 完整分页。语义搜索明确限定最相关前 100 张。响应缺字段、分页重复、上游错误均报错，不当作空结果。

规则相册用持久化的远端 ID 定位；创建描述包含本实例/规则唯一标记，失败重试可找回，不接管同名相册。自动增减时先加后移出，添加失败不执行移出；部分成功可重试。不删除资产。相册编辑和执行通过文件锁串行，worker 也限制单实例。

绑定 Immich 地址和 API key 所属用户；切换实例或用户会停止自动任务。失去权限的 ID 不会换成同名人物/标签。未知版本停止写入，防止使用错误的接口语义。

合并在本地事务中对照片 ID 求并集，保留最早创建事件的 ID，并改写所有相关规则的事件引用。删除保留隐藏事件记录及成员 ID，阻止再次自动生成；不请求 Immich 删除照片或相册。引用已删除事件的规则暂停，不能将删除事件解释为“不限事件”。合并、删除和相册写入共用锁，避免更新交错。

## 0.4.2 目标：活动以 Immich 标签保存

“事件”保留为界面中的整理用语，存储统一采用 Immich 活动标签。名称、层级及照片归属以 Immich 为唯一数据源，例如 `事件/2026/杭州三日游`。Aura 通过公开 API 读取和操作标签，不再维护独立活动目录或活动到照片的成员副本。

0.4.2 仅迁移存储与现有整理操作，保留日期/6 小时分组。跨日活动、人物重合度、画面证据、自动命名及拆分在 0.5 实现。

| 操作 | 目标行为 |
|---|---|
| 生成/命名 | 创建或更新归属 Aura 的活动标签，关联照片 |
| 合并 | 调整标签成员并迁移相册规则引用；核验完成后清理废弃活动标签 |
| 删除活动 | 删除对应活动标签，保留照片；记录不再自动生成的意图，暂停引用该标签的规则 |
| 组合相册 | 事件条件转换为稳定标签 ID，直接交给 Immich 查询 |
| 在 Immich 人工调整 | 读取最新名称/成员并保护人工决定，不用本地旧结果覆盖 |

Aura 保留自动整理规则、受管理标签 ID、纠错保护、删除抑制与任务执行记录。它们用于控制自动化，不能演变成另一份活动名称/成员主数据。普通标签和未经明确接管的标签不受自动整理影响。

迁移现有 `events` / `event_assets` 后，逐项核验名称、成员和相册规则的标签引用，再退出旧运行表；不长期双写。跨服务操作采用可重试的分步任务，成员写入未核验成功前不删除旧标签；重启后不重复创建标签。只读 SMB 场景下须实测标签变更及 XMP 写回，不修改只读挂载来绕过问题。标签整合须通过 0.4.2 的持久性验收；活动识别另按 0.5 验收。当前只读外部库的 XMP 写回失败会导致元数据刷新后丢失标签关联，迁移尚未启用，详见 [实测说明](event-tag-persistence.md)。

## 迁移

Schema 5 → 6：旧待确认时间事件标记为自动通过；旧人工确认事件保持固定，拒绝事件转为隐藏删除记录。升级不改变事件 ID、成员和相册规则。

Schema 4 → 5：先用 SQLite backup 归档旧数据库，在事务中将事件成员、人物/标签条件转换为 Immich ID，再替换运行表。旧本地命名/审核和原规则另存迁移记录，完整资料保留在归档。旧名称仅在对应 Immich 人物未命名时一次性补入，支持幂等重试，随后解除相关规则暂停。名称冲突、本地审核或缺失映射的规则暂停，必须重新预览并保存；不自动向 Immich 回写旧审核。新库不包含旧表，也不运行双写。

恢复 Aura 0.3 需停止 Aura、恢复归档数据库并使用旧版代码。此操作不回滚 Immich；Immich 升级遵循官方指引，不以降级镜像作为回滚方式。

## 兼容维护

唯一上游适配器为 `aura/immich.py`，当前支持 `3.3.4`。依据[该版本 OpenAPI](https://github.com/immich-app/immich/blob/v3.3.4/open-api/immich-openapi-specs.json)及真实实例验证：

- 版本和用户身份、人物/标签读取；
- 新式搜索 `filter`、cursor 分页、语义搜索；
- 缩略图代理；
- 相册创建、通过搜索读取成员、成员添加和移出。

测试覆盖迁移留档、未知版本/用户阻断、分页异常、空交集、失败重试、相册复用及移出保护。`aura-check --write-test` 用独立临时相册验证真实接口并清理它；不操作已有用户相册。空图库跳过成员验证，报告会明确指出。

升级时先在测试实例适配并验证，再更新代码中的 `SUPPORTED_VERSIONS` 与 compose/env 固定版本。白名单是验证结果，不是用户可配置的免责开关。无需 fork Immich；未来 API 变化只修改适配器和契约测试。
