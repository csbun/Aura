# 架构

Immich 是图库唯一来源：照片、人物、普通标签、元数据、缩略图及识别均由官方服务提供。Aura 仅调用公开 API，不读取上游数据库、不挂载原图、不维护照片/人物/标签副本。

## Aura 拥有的数据

- 事件：UUID、名称、时间范围、Immich 照片 ID 关联、自动/人工状态和纠错记录。
- 已处理照片 ID：防止删除事件后再次生成原成员事件，不保存照片属性。
- 相册规则、对应 Immich 相册 ID、任务状态和实例绑定。

事件是 Aura 的新增信息，保存在 SQLite。事件生成、改名、合并、删除都只改本地数据；不生成标签、相册或 XMP。只有用户保存相册规则后，才向 Immich 创建/更新相册。

## 查询与自动化

当前按日期/6 小时间隔分组，跨日活动识别在 0.5。自动事件可扩充；人工改名或合并后保持固定。合并在事务内去重成员并更新规则；删除保留抑制记录及远端相册，关联规则暂停。

人物、普通标签、时间、地点通过 Immich 搜索；事件成员在 Aura 求交。`event` 兼容单事件，`event_ids` 支持多个事件同时满足。普通查询完整分页；语义查询为前 100 张再求交。上游不可见照片不出现在预览中，但不会因暂时离线或权限变化而删除本地关联。

Web 与 worker 使用共享文件锁，SQLite 事务保护本地变更。每天更新事件、每 5 分钟执行相册规则；读取未完成或失败不修改已有事件。相册更新先加后移出，失败不清空；创建标记用于重试复用同一相册，不接管用户同名相册。

## 迁移与兼容

Schema 8 将事件从标签迁回，见[迁移说明](local-events.md)。Schema 6 及更早本地事件直接转成 UUID，并更新规则；此前图库去重迁移仍保留归档及缺失映射保护。

固定官方 Immich 3.3.5，单一适配器 `aura/immich.py` 负责版本、身份、搜索、人物/标签读取、缩略图与相册 API。标签完整成员读取仅用于一次迁移，不再提供标签写入或队列权限依赖。

版本未验证、实例地址或用户改变会停止自动写入。升级先通过契约测试和真实实例检查，再更新白名单；不 fork Immich。`aura-check --write-test` 使用独立临时相册测试增减并清理，不触碰用户相册或原图。
