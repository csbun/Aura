# 架构：Immich 是唯一照片和事件数据源

0.4.2 已部署，样本库的 199 个事件已迁移为标签；前置条件和实测记录见[持久性验证](event-tag-persistence.md)。

```text
照片及 XMP → 官方 Immich ←公开 API→ Aura Web / worker
             照片、人物、标签       规则、自动化状态、重试任务
             事件名称及成员         定期维护 Immich 相册
```

## 职责与数据

Immich 管理照片、元数据、人物、标签、缩略图和语义搜索。Aura 无原图挂载，不访问 Immich 数据库，不修改其源码。浏览器只访问 Aura 后端代理；密钥不交给前端。

事件是 Aura 的整理用语，名称和照片成员直接读取 Immich `事件/<名称>` 标签。普通标签不会自动接管；管理权由本地记录的标签 UUID 决定，不依靠名称匹配。父标签重名时创建独立名称，同名事件添加序号。

SQLite 保留相册规则、受管理标签 ID、自动/人工状态、内容指纹、已处理照片 ID 和任务状态。指纹用于识别人为修改，已处理 ID 用于防止删除后重建；不保留事件名称或事件到照片的成员表。未完成操作临时保存预期写入，成功即删除。迁移完成后删除旧运行表，仅保留离线归档。

## 自动化与纠错

默认每日整理照片、每 5 分钟执行相册规则。0.4.2 保留日期/6 小时分组；跨日完整活动识别和自动命名在 0.5。

- 新照片可补入自动标签。在 Immich 改名或改成员后，Aura 将其视为人工整理，不再自动扩充。
- 合并先核验目标成员、转换规则，再解除旧标签关联并删除旧标签；保留首个所选标签的 UUID。
- 删除只清理标签，保留照片和既有相册；已处理照片不自动重建事件，引用失效标签的规则暂停。
- 查询将事件条件转成 `tag_ids`，与人物、时间等条件统一交给 Immich。普通搜索完整分页；语义搜索最多 100 张。

跨服务操作使用可恢复任务，改名、关联、解除关联后等待 Sidecar/元数据队列完成，再核验并继续。超时、权限不足、失败队列或人工冲突会暂停任务。取消非迁移任务保留已经发生的远端变更，不执行隐式回滚。

图库 key 决定照片范围；可另配管理员 `IMMICH_JOB_API_KEY`，仅用于 `GET /jobs`。无队列读取权限时拒绝标签写入。所有可见图库必须支持 XMP 读写；Docker 部署默认启用 `AURA_EVENT_TAGS_ENABLED`，可显式设为 `false` 暂停事件写入。队列等待是串行化保护，不是上游事务锁；另一客户端同时写入仍可能产生冲突，Aura 核验失败会保留任务而不报告成功。

Web 和 worker 共享 SQLite 与文件锁。规则相册用远端 ID 定位，创建标记用于失败恢复，不接管同名相册。更新先加后移出，添加失败不移出。实例地址、用户或上游版本变化会停止写入。

## 0.4.2 迁移

Schema 6 → 7：先归档 `aura.pre-0.4.2.sqlite`，旧表改为迁移暂存表。逐项创建和核验标签，将规则中的数字事件 ID 转成标签 UUID；全部成功后移除暂存表。旧删除事件转为抑制状态，关联规则仍暂停。重启续跑未完成步骤，不重复创建已核验标签。

恢复旧版本须停止所有 Aura 容器、恢复归档并使用旧代码；仅替换镜像无法回退数据库。恢复 Aura 不会自动撤销已经写入的 Immich 标签或相册。

## 历史迁移

Schema 5 → 6：旧待确认时间事件标记为自动通过；旧人工确认事件保持固定，拒绝事件转为隐藏删除记录。升级不改变事件 ID、成员和相册规则。

Schema 4 → 5：先用 SQLite backup 归档旧数据库，在事务中将事件成员、人物/标签条件转换为 Immich ID，再替换运行表。旧本地命名/审核和原规则另存迁移记录，完整资料保留在归档。旧名称仅在对应 Immich 人物未命名时一次性补入，支持幂等重试，随后解除相关规则暂停。名称冲突、本地审核或缺失映射的规则暂停，必须重新预览并保存；不自动向 Immich 回写旧审核。新库不包含旧表，也不运行双写。

恢复 Aura 0.3 需停止 Aura、恢复归档数据库并使用旧版代码。此操作不回滚 Immich；Immich 升级遵循官方指引，不以降级镜像作为回滚方式。

## 兼容维护

唯一上游适配器为 `aura/immich.py`，当前支持 `3.3.4`。依据[该版本 OpenAPI](https://github.com/immich-app/immich/blob/v3.3.4/open-api/immich-openapi-specs.json)及真实实例验证：

- 版本和用户身份、人物/标签读取；
- 新式搜索 `filter`、cursor 分页、语义搜索；
- 缩略图代理；
- 相册创建、通过搜索读取成员、成员添加和移出；
- 标签层级、改名、关联/解除关联、删除，以及队列状态读取。

已通过真实队列等待、两照片完整操作流程和 199 个事件迁移验证；全部 942 张样本重新提取元数据后，标签成员和名称仍与迁移归档一致。

测试覆盖迁移留档、未知版本/用户阻断、分页异常、空交集、失败重试、相册复用及移出保护。`aura-check --write-test` 用独立临时相册验证真实接口并清理它；不操作已有用户相册。空图库跳过成员验证，报告会明确指出。

升级时先在测试实例适配并验证，再更新代码中的 `SUPPORTED_VERSIONS` 与 compose/env 固定版本。白名单是验证结果，不是用户可配置的免责开关。无需 fork Immich；未来 API 变化只修改适配器和契约测试。
