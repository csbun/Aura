旧数据库保存在 `data/aura.pre-0.4.2.sqlite`。测试临时标签和相册均已清理。

当前运行挂载仍为 `/samples` 可写、`/photos` 只读；读写 NAS 配置尚未应用，真实 NAS 账号的写入权限也尚未验证。

此前只读样本库在重新提取元数据后丢失标签；样本挂载获准可写后解决了 XMP 落盘问题。快速连续操作另发现异步写入冲突，现通过等待 Sidecar/元数据队列、逐项核验和可恢复任务保护后续操作。验证脚本读取样本文件只用于验收，Aura 本身仍不访问原图或 XMP 路径。

上游 `TagService` 更新标签后异步排队写 XMP；`MetadataService` 从元数据恢复标签。两步不是同一个事务。[固定版本源码](https://github.com/immich-app/immich/blob/v3.3.4/server/src/services/tag.service.ts)与实际运行代码均支持这一处理链。[只读库问题 #30979](https://github.com/immich-app/immich/issues/30979)记录了标签丢失现象。

## 配置与检查

在 Immich 管理员账号下创建仅含 `job.read` 的 API key，在 `.env` 填写 `IMMICH_JOB_API_KEY`。它仅供 Aura 读取队列；`IMMICH_API_KEY` 保留样本用户的 key，不扩大图库范围。

照片 key 除读取和相册权限外，需要 `tag.create`、`tag.update`、`tag.delete`、`tag.asset`、`asset.update`、`job.create`。若照片 key 本身已有管理员任务读取权限，任务 key 可以留空。

在测试实例重建后，选一张没有标签的独立样本：

```bash
docker compose exec aura aura-check --tag-test-asset <测试照片UUID>
```

检查创建临时标签、关联、等待写入、刷新元数据并清理标签。已有标签时拒绝执行；超时、失败队列、权限不足、响应异常和关联丢失均不算通过。测试标签被人工改名/移动时停止清理并提示。

Docker 部署默认 `AURA_EVENT_TAGS_ENABLED=true`，启动自动迁移，无需手动扫描。此检查用于验收或排障；所有可见图库都必须实际可读写。仅设置挂载 `rw` 而 NAS 账号或目录仍拒绝写入，不满足部署要求。

## 迁移与恢复

Schema 7 先归档 `aura.pre-0.4.2.sqlite`，将旧表保留为迁移暂存。每个事件创建标签、核验完整成员、转换规则引用，全部成功才删除暂存表。成功操作不保留名称/成员副本；失败任务可重试，人工冲突暂停。

合并先核验目标，再解除旧标签的照片关联、等待写入完成，最后删除空标签。删除不删除照片或既有相册，失效规则暂停；已处理照片不会因标签被删而自动重建事件。

回退 Aura 需停止容器、恢复归档并使用旧代码。回退数据库不会撤销已写入的 Immich 标签或相册。队列等待不锁定其他客户端；并发人工编辑仍需由核验发现并停止冲突操作。
