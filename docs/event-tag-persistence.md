# 0.4.2：标签持久性前置验证

当前状态：标签 API 适配和检查工具已实现，事件迁移尚未启用，仍运行 0.4.1 的事件存储。

## 实测结果

2026-10-22，在当前 Immich 3.3.4 的只读 `/samples` 上选取一张无标签样本：

1. 创建临时标签，关联照片、搜索、改名、解除关联均成功。
2. Immich 日志报告创建 `.xmp` 失败，挂载保持只读。
3. 再次关联临时标签，等待 Sidecar 队列结束，提交该照片的 `refresh-metadata`。
4. 确认元数据刷新完成后，标签关联已丢失；临时标签已清理，未改动原图。

[官方 XMP 文档](https://github.com/immich-app/immich/blob/main/docs/docs/features/xmp-sidecars.md)说明了外部库写回要求；[上游问题 #30979](https://github.com/immich-app/immich/issues/30979)记录了只读库标签在元数据提取后丢失的同类问题。仅测试创建/搜索成功不足以判断可以把事件交给标签保存。

## 检查工具

在明确选定的、没有既有标签的独立测试照片上执行（UUID 可从 Immich 照片地址获取）：

```bash
docker compose exec aura aura-check --tag-test-asset <测试照片UUID>
```

本提交需先重建镜像才能在容器中使用该命令；当前运行服务未因本次验证而升级。

检查会创建临时标签、关联该照片、等待队列、刷新元数据并清理标签。已有标签时拒绝执行；超时、权限不足、响应不完整和关联丢失均返回非零退出码。测试标签被人工改名/移动时停止自动清理并明确提示。此检查不迁移事件，也不修改原有相册规则。

等待队列还要求能访问管理员任务接口；当前普通测试用户调用 `/api/jobs` 返回 403，工具会在创建标签前拒绝继续，不能将权限不足当作通过。上述只读丢失实测另通过单照片刷新及更新时间观察完成。

除现有读取权限外，需要 `tag.create`、`tag.update`、`tag.delete`、`tag.asset`、`asset.update`、`job.read`、`job.create`。标签批量操作需逐项成功；删除含子标签的标签会被拒绝。

## 待确认的测试环境变更

已准备可选配置 `docker-compose.samples-xmp.yml`，尚未启用。将它加在 `docker-compose.samples.yml` 之后会把**本地 `sample-photos/` 挂载改为可写**，允许 Immich 写 `.xmp`。这也给予容器修改/删除该目录内样本照片的权限，不是仅允许写 XMP。真实 NAS 的 `/photos` 仍只读。

启用后必须重跑持久性检查，确认标签经过元数据刷新仍保留，才能继续验证事件迁移。不要通过暂停元数据队列或恢复 Aura 的成员副本来掩盖问题。

该可选配置只解决样本测试条件。真实 NAS 仍只读时不能直接照搬标签方案；正式接入前同样需要解决 XMP 持久化方式，或重新选择能满足原图只读约束的存储方案。

## 迁移实施顺序

1. 验证目标图库的标签持久性和权限。
2. 将现有事件创建为受管理标签，逐项核验照片关联；同名事件处理唯一名称，不接管普通标签。
3. 相册条件转换为标签 ID，核验规则结果；跨服务步骤使用可恢复任务记录。
4. 切换界面和自动整理到标签，核验人工改名、合并、删除及重试行为。
5. 退出 `events` / `event_assets` 运行表，仅保留任务、规则、标签 ID 和纠错保护状态。

当前阻塞在第 1 步，不能标记 0.4.2 完成。
